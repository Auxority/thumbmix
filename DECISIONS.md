# Decisions

Settled choices about how Thumbmix behaves, with the reason, so nobody proposes undoing one by accident. Read this before changing existing behaviour. A decision changes only when the user asks; then edit its line here in the same PR. Finished TODOs leave `TODO.md`; anything lasting they decided goes here.

## Platform

- **The app is called Thumbmix** (2026-10-16): it says what the app is for, mixing with one thumb on a phone, and fits under the home-screen icon. A web search found no app or product by that name (ThumbJam, a music app, is the nearest); no trademark search was done. The name leaves out "Midas" and "M32", Music Tribe's marks, which the description may still name. Settled before 1.0 because the bundle ID, repo, SideStore source and URL scheme all carry it.
- **Latest M32 firmware only** (2026-10-12). No fallbacks for older firmware; X32 and X Air are out of scope.
- **As few permissions as possible, and no data collected** (2026-10-12, the user is privacy aware): Thumbmix asks only for Local Network, to reach the desk. No analytics, tracking or accounts; anything new that needs a permission has to justify it. The SideStore source copies only that one permission (`scripts/sidestore-source.sh`), so a new one also goes there, or SideStore refuses the install.
- **A shake shares this run's log** (2026-10-26, the user's pick after trying it on the phone; a link on the Connect screen and a button beside Disconnect were mocked, `notes/mocks/2026-10-26-share-log`): for a GitHub issue. A shake on any screen asks "Share this run's log?"; Share hands a text file to the share sheet, and the desk stays connected. No button anywhere, no log file of the app's own and no link to GitHub: iOS lets an app read back only its current run (`OSLogStore`), and reporters share right away. The log names desks, channels and network addresses, never a person, and leaves the phone only when its owner shares it. Reading it takes seconds on a phone, so it starts at the shake, off the main thread.
- **iOS 26 and newer, iPhone only** (2026-10-12): the first iOS with glass, on the same devices as iOS 27 (iPhone 11 and SE 2nd gen onward).
- **SideStore reads a source on a `sidestore` branch** (2026-10-12): a raw GitHub link, since `main` is protected and Pages adds settings and a deploy job. Each release rebuilds it whole from the GitHub Releases and force-pushes it as the branch's only commit, so nothing can drift or need merging.
- **SideStore's "What's new" lists the user-facing PR titles** (2026-10-13): each version's `localizedDescription` takes the `feat`, `fix` and `perf` lines of its GitHub release notes, without prefix, author and link, capitalised ("• A woken link drops…"). Docs, test, CI and chore titles mean nothing to a user, so they're left out; a version with none gets no notes rather than an empty one.
- **Unused code runs weekly on main, not on every PR** (2026-10-22, the user; before that its own CI job beside `check`, 2026-10-20): `swiftlint analyze` is single-threaded with no faster mode (its index-store `dead-code` command never shipped; Periphery went commercial), and it made every PR wait 2.5-5.5 min on a second runner. `.github/workflows/unused.yml` runs Mondays and by hand; agents still run `scripts/unused.sh` before a push. So a person's PR can ship unused code until the next weekly run.
- **The full UI suite also runs weekly on main** (2026-10-26, the user, over a PR check): on GitHub's free `xcode-27` runner (3 M1 cores, 7 GB) it passed in ~19 min on one simulator clone; two clones took 30 min and starved the app (a black screenshot, an app killed mid-test). `.github/workflows/ui.yml` runs Mondays and by hand; agents still run it on the Mac before a PR. A failed run mails whoever last edited its schedule.
- **A PR that changes only Markdown skips CI's `check`** (2026-10-16, the user: no CI when no code changes). The job is skipped by `if`, which GitHub reports as success, so the required checks pass; a `paths` filter would leave it pending. Pushes to main always run in full, since Release builds main's newest green commit.
- **`main` takes squash merges only, through a ruleset without bypass** (2026-10-17): Release versions from the commit titles on `main` and SideStore's notes come from PR titles, so one commit per PR, titled by the PR. Rebase merging would let every branch commit bump the version. The ruleset (Settings › Rules) requires a PR and CI's `check`, and blocks force-push and deletion; tags and the `sidestore` branch stay free for Release.
- **No code of conduct yet** (2026-10-17, the user): it needs a public contact for reports. Add one once people other than the user post in issues or Discussions.
- **Connect reads only the overview; a tab is read when it opens** (2026-10-12, after a spike; the user: "read less"). Reading all ~6150 values before going live took ~5 s at a 5 ms round trip (simulated), the overview's 610 ~0.6 s (690 since solo joined it, 2026-10-13: S is on every tab, and an unread switch ignores taps). An opened tab is read first (~0.1-0.25 s of dimmed rows, nothing moves); then strips in use (named and fader up, plus linked partners; a named spare with its fader down waits until opened) fill in the background, tab by tab: Input, EQ, Comp, Sends, Gate, Fed by. A strip that comes into use mid-show is read when opened. A resync forgets everything beyond the overview and reads it again: a value read before an outage may have changed on the desk.
- **No Periphery** (2026-10-17, the user: no outdated project, least of all in CI): its open-source repository was archived on 2026-08-12 for a paid product, and Homebrew disables the formula on 2027-08-12. It ran in CI for one PR (#143); the dead code it found stays removed.
- **Unused code fails CI through SwiftLint** (2026-10-17, the user's pick over a Periphery fork): `scripts/unused.sh` runs `swiftlint analyze` with `unused_declaration`, `public` included (Core is a package, so nearly all of it is public), over clean app and Core builds, tests included so test-only code counts as used. It doesn't flag a needless `public`, which Periphery did. `unused_import` stays off: it flagged an import its file needs. SwiftLint's size and complexity rules cover the tests too since then. Agents run both before a push (Claude Code hook, `.claude/hooks/check-before-push.sh`); a person's push isn't held up and CI catches it.
- **No duplication check in CI** (2026-10-19, after a trial of PMD CPD 7.28, the only free local tool that reads Swift): over all 192 Swift files it found nothing at its default 100 tokens and 9 spots at 60, the largest 13 lines. None was worth a change: parameter tables, the Mute and Solo buttons (sharing their label made it longer, #123), and pairs of tests. A gate that never fires costs CI time for nothing. Try it again (`pmd cpd --language swift --minimum-tokens 60 --dir Core/Sources --dir Core/Tests --dir App --dir UITests`) if the code grows a lot.
- **Native iOS UI first**: system alerts, switches, sheets and back buttons stay iOS's own.

## Editing values

- **Hold a slider row to type its value** (system alert, Set only). Any unit or none ("−6", "1k", "L20", "-inf"), decimal comma or point. VoiceOver gets an "Enter value" action.
- **A typed value out of range is refused, never clamped** (2026-10-10): "1000000" on a fader must not set +10 dB. Set reopens the alert saying it's out of range, with the text kept. The fader's low end is −∞, so "-200" is −∞.
- **A drag has one speed** (2026-10-12). Finer drags (½, ¼) came only after the value had moved, so they didn't help a small nudge. Hold-then-drag (it would overload the hold that types a value), slow-finger acceleration and a Fine button were mocked and turned down. Exact values are typed or nudged ±1 dB.
- **No tap-to-step, no hold-to-reset.**
- **A frequency reads with the desk's digits, in the app's units** (2026-10-21): "124.7 Hz", "1.97 kHz", "10.02 kHz" where the desk shows 124.7, 1k97 and 10k02, so the app and the desk name a setting alike. One decimal below 1 kHz; above, kHz cut to two decimals, as the doc's table (p.150) does for all 201 steps. Not the desk's "1k97" notation (Claude's pick, not yet the user's): "kHz" reads at a glance to anyone.
- **No ±1 dB buttons on the Mix tab** (2026-10-17, the user): holding the fader types an exact value, so the buttons only took room. Solo, Mute and the pan sit right under the fader. VoiceOver still steps 1 dB.
- **An unread switch waits disabled and dimmed, like an unread row** (2026-10-14): the on/off chips, Ø and 48V. In full grey it would pass for a real Off, and VoiceOver says no value until the desk sends one.
- **A double-tap resets at once, without asking**: preamp gain to 0 dB, delay to 0.3 ms, Makeup gain to 0 dB, Ratio to 3:1, an EQ band's Freq to its Reset bands frequency, Q to 2, Gain to 0 dB.
- **Changes that are hard to undo ask first, with the system alert**: linking, 48V ("Turn on 48V for Vox 2?", naming a channel that shares the input or a linked partner), Reset bands ("Reset all 4 bands of Kick?"), Reset gate, Reset comp and Reset input ("Reset the input of Vox 2?", naming a channel whose gain it also changes), and polarity ("Flip the polarity of Kick?", which also explains it). "To Main LR" asks both ways ("Take Kick out of the main mix?" / "Send Kick to the main mix?", 2026-10-13): out can drop a vocal from the PA, in can put a click or talkback on it. The reset alert names no frequencies: they mean little to non-technical users, and engineers know their desk.

## Layout

- **Solo from the overview by holding a name and dragging, as Photos selects** (2026-10-19, after four mock rounds and an independent UX review, `notes/mocks/2026-10-19-solo-overview`). Made for hunting a noise by halves, at soundcheck and mid-show. Tap a name opens the strip; hold it ~0.3 s and it solos; keep holding and drag up or down the names, and every row passed gets the same state; starting on a soloed name unsolos the run. Only the name column starts a stroke, so faders and M never move. An S on every row (shorter faders), a button beside the tabs (narrower tabs), a solo mode and a solo sheet were turned down. No Undo (Clear covers it) and no help page: the app teaches the gesture itself, with a tip above the tabs until the first hold-solo.
  - **A soloed strip's name is yellow everywhere it shows, and says "Solo" in words**: "1 · Solo" under it on the overview, "Ch 9-10 · Solo" on Sends, Fed by and DCA Members, "Ch 1 · Solo" as a strip's title. Yellow alone fails colour-blind engineers; an icon shifted the name and shortened the room for it.
  - **"N soloed · Clear" sits above the tabs while anything on the desk is soloed**, wherever it was soloed. Clear is the desk's CLEAR SOLO (doc p.69). The rows on screen never move when it comes or goes.
  - **Exclusive solo is asked about once** (option C): the desk keeps one solo at a time (doc p.21), which spoils a run. When a stroke reaches a second strip, the rest of the run waits, dimmed, and lifting the finger asks "Turn off" or "Keep". Keep holds for that desk until the app quits. The app never turns it off unasked, and never borrows it silently like the RTA.
- **The Mix tab: fader, −1 | +1, SOLO | MUTE, pan** (2026-10-13, after five mock rounds). Solo and mute are hit mid-show, so they get the bigger targets. Every other tab's slim row is fader | S | M (letters keep the fader wide; the overview's mute already reads "M"), so a channel can be soloed while its EQ is shaped.
- **The Connect screen is built for one thumb** (2026-10-15, layout E after four mock rounds, `notes/mocks/2026-10-15-connect-screen`). Bottom up: a quiet "Try a demo console" link, Scan again | Enter IP, and the console used last as a card with one big Connect; other consoles are listed at the top. A status area above the list (counts, help steps) was mocked and turned down as busy.
  - **A fresh start opens the Connect screen**; nothing connects by itself. Coming back from the background keeps the connection. A console that answered this visit's scan is marked Online, one that didn't "Not found" and still tappable; before the scan answers a row shows no state. While the screen is open it scans again every 5 s, quietly (the button doesn't flip to "Scanning…"): a desk switched on after the screen opened, still booting at the first scan, stayed Not found until a restart (2026-10-26).
  - **Every console that connected as an M32 is remembered**, by its address and the name set on the desk (`/xinfo`), so two venues' desks on one address stay apart. Swipe a list row to forget it; the card has no swipe. The scan also asks remembered consoles directly, so one on a routed VLAN can show Online.
  - **A scan never moves a row**: a console found later goes below the others.
  - **Problems are system alerts in short questions** ("Can't reach Zaal 2" / "Is this iPhone on the desk's Wi-Fi, with Local Network on for Thumbmix?", with a Settings button), never text that pushes the list down. Enter IP is a system alert that starts from this phone's network ("192.168.1."); the M32 has no IPv6 (neither the manual nor Maillot mention it).
- **The overview has no title** (2026-10-15): its bar holds Disconnect and, in Offline mode, the DEMO pill alone in the middle, so showing it moves nothing.
- **Gate and Comp put the graph first, then On and Mode** (2026-10-15), like the EQ tab. Until its values arrive the graph draws only its 1:1 line, so On never moves under the thumb. Threshold stays on the SE's first screen.
- **The Insert block sits on the Mix tab, under Pan and Link** (2026-10-14, mock A′ over a Comp-tab-end block and one compact row). Strips with an insert: channels, buses, matrices, Main LR and Main M; aux ins, FX returns and DCAs get no block. Rows: Slot (full width, outlined, no chevron), then an Insert chip beside a Position menu, then "Set on the desk".
  - **The slot is read-only** until m32-probe says what picking a slot another strip holds does. The Slot row sits where a menu will go (`insert-slot-future-v2.html`), so making it editable moves nothing. It names the effect from `/fx/N/type` ("FX5 L · Dual DeEsser"), or "Aux out 1 · outboard"; slot Off reads "None" and disables the chip and Position.
  - **Position shows "Before EQ / After EQ"**, the desk's PRE / POST as the subtitle, like Comp position. The X32 quick-start manual says "Insert point (swappable between post-EQ and pre-EQ operation)" for buses, mains and matrices; for input channels it is unverified (m32-probe). The closed row shows the desk's PRE / POST.
  - **Only an aux slot asks before the insert goes on** ("Turn on the insert for Vox 1?"): the strip then plays only what returns from the gear on that aux out, and with nothing patched it can go silent; the app can't see what's patched. An FX slot always returns sound, off only removes processing, and Position is two taps, so they change at once. The alert goes if the probe shows the desk doesn't silence an unpatched aux insert.
  - **A linked pair gets one block, per side when the desk doesn't share the Dynamics link, a side didn't follow an edit, or the read On/Position differ** ("FX5 L / R · Dual DeEsser", or both slots when mixed; the alert asks if either side is aux). On and Position are written to one side and the partner re-read, like the other non-fader sections.
  - **The Dynamics link carrying inserts is an assumption**: no manual, forum or video found says which Link Preference governs inserts (searched 2026-10-14). If it's wrong, after the first insert edit on a pair the desk doesn't copy, the pair's insert, Gate and Comp show per side until reconnect. This fails safe: the partner is re-read, so a stale value never shows as live.
  - **The Mix tab scrolls** (`.scrollBounceBehavior(.basedOnSize)`, so a strip that fits never moves). A slanted-drag UI test guards the big fader on a pair.
- **"To Main LR" is a pill on the Mix tab's name line** (2026-10-13). Rejected: a button beside MUTE (cluttered), a chip before the pan (awkward with a pair's two pan rows), its own On/Off row ("feels off"), Sends or every tab's header (it belongs on Mix). On: speaker and "LR" on a green tint; off: crossed speaker on grey; fixed width, so it never resizes. The icon, not colour alone, tells the state.
- **A state that's on almost all show is tinted, not filled** (2026-10-13): fills mean "look here" (SOLO, MUTE, 48V, Ø). In the main mix is the usual state, so the LR pill is tinted; so are the send On chips in Sends and Fed by, nearly all on.
- **A send's chip says On, never an inverted M, and Fed by rows show no strip mute** (2026-10-14, the user: "let's not use Muted when it should be on"). The chip names the state it's in most of the show. The source's own mute stays on the overview and its Mix tab: rejected were an M beside On (two mutes in one row, one of them silencing the strip everywhere) and an M in the send sheet.
- **Sends and Fed by rows show a named strip's desk number under its name, like the overview** (2026-10-13): "Kick" over a small grey "Ch 1", so two "Vox" rows can be told apart. Unlike the overview's bare "1" it names the kind, as Fed by mixes channels, aux and FX; unpadded, like the overview ("Ch 9-10"). An unnamed strip shows only its title, "Ch 13", which is the number. Four mock rounds picked a grey "CH 12" tag (mock L), dropped for consistency with the overview. Rejected: the number before the name or in a gutter, kind headers with bare numbers (too busy), coloured tags.
- **The overview's groups and a strip's tabs are one pill bar at the bottom** (2026-10-16, mock S after four rounds and a UX review; the 2026-10-12 glass bar, mock A2, from real iOS 27 screenshots): one dark glass capsule, in thumb reach, its pills equally wide and at least 44 pt tall (36 pt got missed). **Since 2026-10-29 the bar is iOS's own segmented control** (`.extraLarge`, 49 pt) on that glass, the user's pick of native over our own (`notes/mocks/2026-10-29-glass-pills`): a thumb sliding across it carries the system's glass lens, rainbow edges included, and opens the segment it's released on. A `TabView` was turned down: on a 375 pt screen it shows four tabs and puts the rest behind More (Comp and Sends hidden). So was our own lens on the old white pills (custom, unlike iOS). The 2026-10-16 white pill that slid over in a fixed 0.2 s went with it. Nothing scrolls, so every group and tab is one tap, always in the same place. The overview's pills say In · Aux · FX · Bus · DCA · Main · Mtx (the desk prints BUS and MTX); VoiceOver reads the full names. Rejected: pills sized to their words (unequal), full names that scroll (half the groups off screen), capitals (MAIN too tight), the L | R picker as pills (reads as a second tab bar).
- **A send's settings open in a sheet** (2026-10-12, mock H, picked over a pushed send screen and four inline layouts): a › on the send row opens a half-height sheet of black-tinted glass, picked from real iOS 27 screenshots. The sheet keeps you on the Sends tab, in thumb reach, closes with a swipe down, and the strip's fader and mute above it stay usable. Sheets are for details of where you are (like Edit strip), pushed screens for going somewhere. A stereo mix's sheet, with its pans, drags up to full height.
- **Sends come in pairs, each with one tall ›** (2026-10-12, mock B over a › per send): the desk keeps one tap point per pair of buses, so an unlinked pair's two rows share a › and one sheet ("Vox 1 → Mon 1 & Mon 2", both levels, one tap point), and nobody changes "Mon 2's" tap point thinking it's Mon 2's alone. A linked pair is one send, like on the desk. The pans show only for a linked pair, since a send pan does nothing on a mono bus. A linked source gets a send pan per side, like its LR pan, and one Follow LR pan switch for both.
- **The bus names in a send pair's sheet title are links** (2026-10-12, mock A over rows at the bottom, a title menu and a button per row): blue like iOS's own links. Other mixer apps are bus-first (Mixing Station, Yamaha StageMix: pick a bus, the channel faders flip to its sends) and none documents a jump from a send. So the bus opens on its Fed by tab, Thumbmix's version of that flip, with the source's row in view; Back returns to the Sends tab.
  - The source's name is a link too (2026-10-14, the user: "Kick and Mon 1 both clickable"): it opens on its Sends tab, where the send is a row. The strip already on screen (either side of a linked pair) only closes the sheet (`ChannelTab.opened`).
- **A Fed by row's tall › opens the same send sheet as Sends** (2026-10-14, TODO "An inputs view on buses"): tap point, pans and Follow LR pan of each source, without leaving the bus. Opened from Mon 2 of an unlinked pair it still shows both levels, as they share the tap. The mains have no tap or send pan (`Catalog.sendTap` is nil there), so their rows have no ›. Fed by reads what the sheets show when it opens, after the rows' own values.
- **A send's tap point is a chain of its strip's blocks** (2026-10-12, after eight mock rounds; real iOS 27 screenshots): Input › Gate › EQ › Comp › Fader, in the strip's real order (the comp moves with `dyn/pos`), lit up to where the send is taken, and one sentence on what that means while mixing. Engineers get the consequences wrong, not the labels, so the chain shows what reaches the mix; it replaced a dropdown, which said the same thing twice.
  - Tapping a block takes the send right after it. Tapping the current one does nothing: a nervous double tap mustn't move a monitor mix.
  - One green capsule slides to the new tap point (a spring): fills switched per block looked choppy.
  - Plain names ("Before fader"); the desk's full term sits in the label ("Tap point · Pre-fader").
  - The sentence always takes the longest one's height: nothing below it moves when the tap changes.
  - Subgroup ends the chain: Pan on a stereo mix (it follows the channel's pan), Group on a mono one, so a Subgroup set on the desk never looks like After fader. It asks first with the system alert, since it puts the send at a fixed 0 dB; the other taps change at once.
- **The mains' Fed by lists every strip with an LR switch** (2026-10-13, mock A): inputs, aux ins, FX returns and buses, in or out, so no row vanishes when it flips. Main M's row is the mono send, On (`mix/mono`) and level (`mix/mlevel`), like a bus's; its On switches at once. Main LR has no send level, so its row is the LR switch and the strip's own fader, the same shape as every Fed by row (rejected: the switch alone).
  - A drag there moves the strip's fader, and with it every post-fader send, while the same-looking row on a bus moves only a send. So each caption says it, "Ch 1 · Fader" (mock F1), and one grey line above the list says it again for whoever skips captions (F4). Rejected: the overview's fader row (no longer matches the other Fed by tabs), a slider icon before the value (needs learning).
  - The LR chip asks first, like the Mix tab's pill: a stray tap while scrolling is easier here.
  - The same rows in LR+M and LCR mode, whatever "M/C depends on Main L/R" says: the doc only names both settings (p.21; m32-probe TODO).
- **Unused strips fold into one row at the end of a list** (2026-10-14, mocks A1 + 2 over slim rows in place and one global switch): the overview (every group), Sends and Fed by end in "6 unused · Ch 3, 6, 8, 10, 13–14 · Show"; Show puts them back in their desk spots, dimmed, and the row becomes Hide. With nothing unused there's no row. The list keeps its bottom in place, so Show and Hide never move the row from under the finger (the user: "make sure the scroll position isn't ruined").
  - Unused is unnamed with the fader at −∞; on Sends and Fed by also the send there at −∞, so a live send is never out of reach (why Fed by's old toggle went, #67). An unread level never folds. A linked pair, and on Sends a pair of buses (they share one ›), folds only as a whole. The mains never fold.
  - One open/closed state per kind of list (overview, Sends, Fed by, Members), kept across launches: opening Fed by to find one source doesn't lengthen the overview.
  - A range in the row never wraps inside ("17–32" moves to the next line whole).
- **A DCA's Members tab assigns strips with a chip per row** (2026-10-17, layout D over a whole-row checklist and overview rows lit when in, `notes/mocks/2026-10-17-dca-members`): every strip with a DCA mask, under Inputs · Aux · FX · Buses in desk order, each row shaped like an overview row (S4 of 4, the same day, `notes/mocks/2026-10-17-dca-member-stripes`): the name block on the left, with the overview's stripe (stacked for a pair, outlined when inverted), opens the strip; the chip on the right, where the overview's M sits and nearest the thumb, assigns. The block keeps a button's look (the user); a tint in the strip's colour went, so a strip looks the same wherever it's listed. A tap applies at once, without asking (the user: nobody opens this tab without meaning to view or change who's in). No row moves on a tap.
  - The chip has no word: a filled tick when assigned, an empty ring when not (mock I3). A column of "DCA 1" is text nobody reads (the user); "Assigned" was cramped in the 72 pt chip; an empty chip didn't look tappable.
  - A linked pair is one row, even with its faders unlinked, and a tap writes both sides, as Solo does. A pair the desk holds half assigned says "L only" or "R only"; a tap assigns both. Unused strips fold as on the other lists, but an assigned one never does.
- **The six mute groups live on the Main page** (2026-10-19, after four mock rounds, `notes/mocks/2026-10-19-mute-groups`): a 2×3 grid pinned above the pills, under Main LR and Main M, in reach. A tap switches a group at once, as the desk's key does: groups are switched several in a row between songs, so no hold and no confirm. A hold opens who's in it. A desk group has no name, so each button names its strips. Rejected: an always-there bar above the pills (the user: "too risky", one stray tap mutes a band), a hold to switch (too slow for several at once), a "Groups" pill (too wide; an eighth pill would scroll), a top-bar sheet, an "MG" key beside the pills (an unclear abbreviation), a hold on a strip's M (a slow press must still mute), round buttons (foreign to the app), a "Mute group 2 on" bar on the other pages (the bordered M says it).
  - **A red inner border on a dark red tint means "muted by a mute group"**: on a strip's M and on a group that's on, one signal with a shape besides the colour. A filled red stays the strip's own mute, and wins when both apply.
  - Members are chosen like a DCA's: chips, a tap applies at once, a pair as one row. Every strip but the DCAs can join, matrices and mains too.
  - **A strip picks its DCAs and mute groups in its edit sheet**, sent with the name on Done (S1, over a Groups row on the Mix tab and tags under the name; the user: nobody changes membership during a service, scenes would). Done writes only the ticks changed, so a change made on the desk meanwhile stays. Joining a group that's on says the strip mutes on Done. The icon is a tile with a pencil badge left of the name, its grid a page of its own (A, over a dashed edge, an Edit band and a chevron).
  - **A mute group has a name, kept on the iPhone** (2026-10-31, the user's picks R2-B, Q2-C and Q3 A+B+C from mocks `notes/mocks/2026-10-31-mute-group-names`): the desk has none (doc p.21), so each remembered console (`NetworkConsole.id`, as Connect keeps desks) keeps six names in `UserDefaults`, gone with the console when Connect forgets it. 12 characters under a strip name's typing rules, with its n/12 counter (`NameField`, shared with the edit sheet); empty is unnamed. A pencil beside the name above the members page's wide button (as a strip's `ChannelHeader`) opens a Cancel / Done sheet; Done works while contact is lost, and the page title stays "Mute group 2". The Main page's button shows the name over "N strips"; an unnamed one keeps its number over its strips, or over "N strips" when SwiftUI's `ViewThatFits` says the names don't fit (the user: "if the text is too long I prefer to only show 'x strips'"). Elsewhere the name shows where the strip is: the caption of a strip row while its group is on ("13 · Band", red), the Groups chips of the edit sheet (cut by the chip) with the whole name in the "Group 2 (Band) is on: …" line, and VoiceOver on the red-bordered M ("Muted by Band", unnamed "Muted by mute group 2"). A strip in two groups that are on names the lowest. Rejected: the name field in place on the members page (a slip of the thumb opens the keyboard), a system alert like a preset's (no counter).
  - **A swipe down never closes the edit sheet** (2026-10-30, the user: a swipe down on a preset closed the sheet and every page on it). Only Cancel, Done and a load close it; swipe-back from a pushed page stays. The send sheet still closes with a swipe down: it holds no draft.

## Presets

- **Presets are the engineer's own, and Thumbmix teaches no sound** (2026-10-27, the user): Save writes a strip's settings On this iPhone, Load puts them on any strip that can take them, Share passes them around as `.json` files, and a file or folder source takes them in. The app ships none of its own making in the binary. The idea began with a book's presets (*Live Mixing Field Guide*), but that is all rights reserved and the app is MIT, so nothing is taken from it; the repo's own starting points come only through the default web source.
- **A preset is a Reset's list with the desk's values** (2026-10-28, the user, over typed parts): per part, the values of the controls `PresetPart.specs` lists, by their address under the strip (`"gate/thr"`, `"eq/2/f"`; the preamp's as `"headamp/gain"`), in real units and the desk's option names. One list per part drives save, load, the check and the preset's page, so a new control is one line. A hand-written part may hold only some values.
- **On this iPhone, and folder, file and web sources beside it** (2026-10-28): `Documents/Presets` shows in the Files app, so files can be copied in and out by hand; it is read again when the Presets page opens, and a file the app refuses is named there. A web source is an HTTPS `index.json` in the SideStore style (`"format": "thumbmix-source"`, a name, relative preset paths); the repo's `presets/` folder is the default one, present on first launch and removable; the app doesn't offer it back (the user, 2026-10-28): the README gives its address to add like any other. A folder or file source is picked in Files and kept by a bookmark (security-scoped on macOS only, where the tests run); a folder reads every `.json` in it, up to 200, through `NSFileCoordinator` with the size checked first, and a file iCloud hasn't downloaded is asked for and named "Still downloading" rather than waited for (a coordinated read would wait for the download, forever at a venue without signal). Folder or file is told by the picked item, not by which menu item opened the picker. A stale bookmark (the item moved) still opens it: it is read and replaced by a fresh one under the same source id, and picking the item again does the same. Every source is read again when the Presets page opens, and each keeps its last good read in Application Support (not Caches, which iOS may clear before the show): a file lost to the network, to iCloud or to a moved folder shows its copy with "Showing the last good read", since a venue without signal is the normal case (the user, 2026-10-28). A file deleted in Files goes, and a refused one never comes back from the copy. A source's presets are read-only: changing one means "Save a copy" On this iPhone. Add is a wide button pinned at the bottom of Sources that opens Folder…, File…, Web address… (pick C, 2026-10-28; mocks in `notes/mocks/2026-10-28-preset-pages/`).
- **A web source can't reach further than its index** (2026-10-27): HTTPS only, also after a redirect; no name, password, query or fragment in its address; preset paths relative, without `..`, on the index's own host. The index is at most 64 KB and 200 presets, each preset 32 KB, the whole read 30 s; the answer must be JSON or plain text in UTF-8. A bad preset is skipped and named, a bad index keeps the last good read, and fetched text is shown only as plain text.
- **One check for every preset** (2026-10-27, `PresetValidation`): every value needs a control on the strip type it was saved from, of the right kind, inside its spec's range. Out of range is refused, never clamped (as typed values are); an off-grid value inside the range is snapped to the desk's step on loading. Unknown options, versions, formats and keys (a misspelt part), a name over 40 characters, more than 10 match words (20 characters each), control characters and files over 32 KB are refused, and a refusal names the path.
- **Loading never raises the gain or changes 48V without asking** (2026-10-27, the user): a system alert per write, one after another: a higher gain or trim, 48V on or off (it names every channel on that preamp), a polarity flip, and a comp move past mixes that hear the difference. "Keep" drops only that write and the rest loads. A lower gain asks nothing. Sending plans again against the desk (2026-10-28): a "Keep" holds even if the desk moved, a yes holds only for the change its alert named, and a write that needs a question nobody was asked (or a changed one) stays out and is reported. Input waits for a linked partner's gain and trim to be read, since the desk copies them there. A strip no preamp feeds loads Input without gain and 48V.
- **Presets leave out what names this desk or this show** (2026-10-27): name, colour, icon, mute, solo and groups, a gate or comp key source (the key filter is kept) and the insert slot. Mix (fader, pan) and Sends start unticked on Save. On Load every part the preset holds starts switched on, Mix and Sends too, and the engineer switches off what to leave out (the user, 2026-10-28); the alerts guard only gain, 48V, polarity and the comp move.
- **A part loads only where it fits** (2026-10-27): EQ needs the same band count, and every value a control the strip has that takes it (mains and matrices have 14 filter types, the rest 6); Gate is inputs only; Sends need the same send targets (buses for inputs, matrices for buses and mains). A part that can't load is greyed with its reason; one still being read says "reading…", since `set` skips an unread control.
- **The way in is one row on the edit sheet** (2026-10-27, the user's pick B2): "Presets · 2 fit “Kick” ›", hidden for DCAs. Match words fit when a strip's own name contains one, ignoring case and diacritics; no words fit nothing. A preset's page is described in the next entry.
- **A preset reads at a glance, and loads from its own page** (2026-10-28, the user, mock rounds 1-5 in `notes/mocks/2026-10-28-preset-pages/`, replacing the Settings-style list of the same day: "no one is gonna read all of that"): a card per part, in the strip's tab order, each its picture (the EQ curve, the gate's and comp's transfer curves without a meter, the Mix's fader on the desk's law and its pan; none for Input and Sends) beside the 2-5 values that change its sound most, in compact numbers ("−18 dB", "4:1", no trailing ",0"). A card opens All values: one panel per group, two cells to a row, the unit small and grey; the EQ's bands as a table, a column per band in the desk's type names (PEQ, HShv…), each number over its unit so "10.02 kHz" fits a quarter of a 375 pt screen. The parts to load are chips above Load, pinned under the page and each part's page (pick F): a tap meant for reading a card never changes what loads, and every choice sits in thumb reach. There is no load sheet. A load that went out closes the presets and the edit sheet onto the strip, where its result shows (the user, 2026-10-29, replacing a page that stayed with "Loaded" for 2 s); with a name, colour, icon or group picked but not yet sent with Done, it goes back to the edit sheet instead, so nothing is lost. A send is listed on a card only while it sends (on, above −∞); All values shows every bus. A bus's name is the one the desk gives it now, only while the desk is live, since a send loads by number.
- **No Import button** (2026-10-29, the user): a file or folder source on Sources takes a preset in; "Save a copy" puts it On this iPhone. `PresetLibrary.importPreset` (copies, a name already taken gets " 2") stays for opening a `.json` straight from AirDrop or Mail, a TODO.

## How we decide

- **Core test fakes stream no meters unless a test asks** (2026-10-20, `startFake(meters:)`): ~80 parallel fakes streaming meters at the desk's 20 Hz took most of a CI runner's CPU, so syncs missed `syncTimeout`. Measured next to N busy processes, the suite failed every sync from N = 15 on `main` and passes at N = 20 without meters. Not chosen, after measuring them: decoding meters off the main actor (~17), a faster blob decoder (~17), keeping only each bank's newest blob and stretching the read timeout (no change). The app reads one desk's meters, far below that load.
- **UI is picked from mocks shown side by side**; glass and material choices from real iOS 27 simulator screenshots, since HTML can't show glass.
- **One app launch per simulator, across UI test classes** (2026-10-23, replacing one per class from 2026-10-12): with 53 tests in 26 classes a launch per class was ~1 in 2 tests. A full run now launches 15 times instead of 26 (one per clone, then on other arguments and after `ConnectUITests` or `OfflineUITests`), ~70 s less test time at ~6.5 s a launch; measured 712 s → 662 s, wall 359 s → 349 s (one run each, and runs vary by more). Per class won on 2026-10-12 (523 s vs 556 s) with 176 tests. A class that launches the app itself (`ConnectUITests`) would hand its app to the next class: a test observer drops it, so no class has to remember a rule.
- **The UI suite stays on 3 simulator clones** (2026-10-23): 6 clones made each class 1.5-2.6× slower (Sends 65 → 132 s), clones 5 and 6 started late, and the Mac became unusable (load average ~970 on 11 cores). The fake desk's meters cost the UI tests nothing (3 alternating runs each: 50.9 s vs 50.5 s), unlike the Core tests'.
- **xcodebuild hands the classes to the clones, not our own slowest-first shards** (2026-10-23): one `build-for-testing`, then a `test-without-building` per clone with a slowest-first share of the classes, balanced the clones (27 s apart instead of 74 s) but took 335 s against `scripts/ui-test.sh`'s 311 s: each shard pays ~85 s to start its own test runner on a fresh clone, more than xcodebuild's idle tail.
- **Left as they are by the code review** (2026-10-15, two copies don't make a pattern yet): `ConsoleMirror` and `Catalog` stay unsplit; the send-sheet setup shared by `SendsTab` and `FedByTab`; the Gate and Comp tabs' shared layout (their curves move to Core with "more comp settings"); the per-kind name stems ("Ch", "Aux"), which would churn the string catalogs.
